This is the repository for the permanent website of the **International Conference on New Interfaces for Musical Expression (NIME)** at <https://nime.org>, including the proceedings archive. It is deliberately a small, static [Jekyll](https://jekyllrb.com) site that links to the PDF proceedings and media files from previous NIMEs, and to archival copies of the websites of previous editions of the conference.

Contact the [NIME Proceedings Officer](https://nime.org/board/) for further details, or email <website@nime.org>.

## Quick start

You will need Ruby (see `.ruby-version`) and [Bundler](https://bundler.io). The site builds with Jekyll 4 and the plugins listed in the `Gemfile`; it does not use the `github-pages` gem, since it is deployed to our own server rather than GitHub Pages.

```sh
git clone git@github.com:NIME-conference/NIME-website.git
cd nime-website
bundle install
bundle exec jekyll serve
```

Then open <http://localhost:4000>. Jekyll rebuilds when you edit a file. The full build takes a while because it generates one page per proceedings entry (several thousand pages).

To build once without serving, as CI does:

```sh
JEKYLL_ENV=production bundle exec jekyll build
```

The output is written to `_site/`, which is ignored by git.

## Repository layout

| Path | Purpose |
| --- | --- |
| `*.md` | Regular pages: `index.md`, `board.md`, `committees.md`, `hosting.md`, `past-nimes.md`, statements, and so on. |
| `proceedings-*.md` | Listing pages for the proceedings archive (papers, music, installations, alt, ISBNs, reviewers, translations, retracted). |
| `_data/*.yaml` | Bibliography data for the proceedings, fetched from the NIME-bibliography repository. Do not edit by hand. |
| `_layouts/` | Page templates. `paper.html` is the template for an individual proceedings entry. |
| `_includes/` | Shared fragments: head, nav, footer, citation and metadata blocks, video embeds. |
| `_posts/`, `_drafts/` | News posts (feed at `/feed.xml`). |
| `assets/` | Images, logos, CSS and JavaScript. |
| `scripts/` | Python checks run by CI (see [Continuous integration](#continuous-integration)). |
| `get_publications.sh` | Downloads the latest bibliography YAML into `_data/`. |
| `_config.yml` | Jekyll configuration, including the per-entry page generator. |
| `.github/workflows/` | GitHub Actions for deployment and quality checks. |
| `.lychee.toml` | Configuration for the weekly external link check. |

## Bibliography and proceedings pages

The NIME archive's BibTeX files live in the separate [NIME-bibliography](https://github.com/NIME-conference/NIME-bibliography) repository, where a GitHub Action converts them to YAML and publishes them at <https://nime-conference.github.io/NIME-bibliography/>. This repository holds a copy of that YAML.

- Run [`get_publications.sh`](get_publications.sh) to refresh the four data files in `_data/`: `nime_papers.yaml`, `nime_music.yaml`, `nime_installations.yaml`, `nime_alt.yaml`.
- The listing pages (`proceedings-papers.md` and friends) are generated by Liquid templates iterating over those YAML files.
- One HTML page per entry is generated by the [`jekyll-datapage-generator`](https://github.com/avillafiorita/jekyll-datapage_gen) plugin, configured under the `page_gen` key in `_config.yml`. Entries land in `/proc/`, `/proc_music/`, `/proc_installations/` and `/proc_alt/`, named by their BibTeX ID.
- Each entry page uses `_layouts/paper.html` and includes Google Scholar citation metadata (`citation_*` meta tags) so the proceedings are indexed.

Corrections to titles, authors or PDF links should be made in the BibTeX in NIME-bibliography, then pulled here. Fixes made directly in `_data/` will be overwritten the next time the script runs.

## Hosting and deployment

- The website is hosted on a standard shared-hosting server.
- On every push to `master`, the [build and deploy workflow](.github/workflows/build-github-pages.yml) builds the site and copies `_site/` to the server with rsync.
- The rsync step **does not delete** files on the server. This is deliberate: some content on the server is not in this repository (see below).
- The proceedings PDFs are far too large for GitHub. They are uploaded by hand to the `/proceedings/` folder on the server by the web officer. Archived copies of past conference websites live in `/web_archive/`. Nothing in this repository should ever overwrite or remove those folders.

Details of the server, credentials and the deploy key are held by the Proceedings Officer and stored as GitHub Actions secrets.

## Continuous integration

Three workflows run in GitHub Actions:

| Workflow | Trigger | What it does |
| --- | --- | --- |
| [Build and deploy](.github/workflows/build-github-pages.yml) | Push to `master` | Builds the site and deploys it to nime.org. |
| [Site quality](.github/workflows/site-quality.yml) | Push to `master`, pull requests, manual | Builds the site, then runs three checks in parallel: html-proofer for broken internal links and assets; `scripts/check_site_quality.py` for page SEO basics, Google Scholar metadata on every proceedings page, sitemap consistency and bibliography data problems; and pa11y-ci (axe and HTML_CodeSniffer) for WCAG 2 AA accessibility on all regular pages and a sample of proceedings pages. |
| [External links](.github/workflows/external-links.yml) | Weekly on Mondays, manual | Runs [lychee](https://lychee.cli.rs) over every external link in the built site and opens or updates a GitHub issue if any are broken. Hosts that block automated checks are excluded in `.lychee.toml`. |

Both checkers skip `/proceedings/` and `/web_archive/`, since that content is not built from this repository.

### Running the checks locally

```sh
bundle exec jekyll build

# Internal links and assets
gem install html-proofer
htmlproofer _site --disable-external --no-enforce-https --checks Links,Images,Scripts

# SEO, Scholar metadata, sitemap and data checks
pip install pyyaml
python3 scripts/check_site_quality.py --site _site --data _data

# Accessibility (needs Node)
npm install --no-save pa11y-ci@3 serve@14
npx serve -l 5089 -n _site &
python3 scripts/pa11y_urls.py _site http://localhost:5089 > .pa11yci.json
npx pa11y-ci -c .pa11yci.json
```

## How to do certain tasks

### Change the text on a regular page (e.g., the location of the next NIME)

1. Edit the relevant markdown file (e.g., `index.md`, `hosting.md`) on GitHub or locally and commit to `master`.
2. The website will automatically build and deploy to the web server within a few minutes. Check the [Actions tab](https://github.com/NIME-conference/NIME-website/actions) if it does not appear.

### Add a new year of NIME proceedings

1. Add a new yearly BibTeX file to the [NIME-bibliography repository](https://github.com/NIME-conference/NIME-bibliography) (e.g., `nime20XX.bib`).
2. Make sure the GitHub Actions on that repository complete correctly. You can check the output YAML on the [NIME-bibliography site](https://nime-conference.github.io/NIME-bibliography/).
3. Run `get_publications.sh` in this repository.
4. Check that the website still builds and displays correctly on your local computer.
5. Commit the updated YAML bibliography files and push.
6. The website will automatically build and deploy. The site quality workflow will flag any entries with missing metadata.
7. Separately, upload the PDFs to the `/proceedings/` folder on the server.

### Fix a paper's title, authors or PDF link

1. Correct the BibTeX entry in [NIME-bibliography](https://github.com/NIME-conference/NIME-bibliography).
2. Once its action has run, run `get_publications.sh` here and commit the updated YAML.

### Update the board or committees

Edit `board.md` or `committees.md` and commit.

### Add a news post

Add a markdown file to `_posts/` named `YYYY-MM-DD-title.md` with `layout: post` front matter. It appears in the RSS feed at `/feed.xml`.

## Contributing

Pull requests are welcome. The site quality workflow runs on every pull request, so a green check means the built site has no broken internal links, no missing page or Scholar metadata, and no WCAG 2 AA violations on the tested pages. Please keep the site small and dependency-light: it is meant to outlive any particular maintainer.
